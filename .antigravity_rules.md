# ANTIGRAVITY PROJECT RULES - Out Of Nothing

Ces règles sont STRICTES et s'ajoutent aux instructions globales. Le non-respect de ces règles est considéré comme un échec de mission.

## 1. WORKFLOW DE MODIFICATION (OBLIGATOIRE)
1. **ANALYSE PRÉALABLE** : Avant de modifier un fichier, lire le fichier complet pour identifier les dépendances et les membres privés/publics.
2. **PLANIFICATION (TODO)** : Mettre à jour `TODO.md` avec l'étape en cours AVANT de coder.
3. **MODIFICATION ATOMIQUE** : Ne modifier que ce qui est nécessaire à la tâche actuelle.
4. **VALIDATION DE COMPILATION** : Vérifier que toutes les propriétés appelées (ex: `TickRate`) sont accessibles et correctement typées.
5. **TRAÇABILITÉ (LOGS)** : Mettre à jour `DEVELOPMENT_LOG.md` IMMEDIATEMENT après la modification pour expliquer le "Pourquoi" et le "Comment".

## 2. RÈGLES DE DOCUMENTATION
- Chaque entrée de log doit contenir : Le problème résolu, la solution technique, et l'impact sur le reste du système.
- Ne JAMAIS supprimer les logs précédents.
- Toujours maintenir une liste de tâches (TODO) claire et synchronisée.

## 3. RÈGLE "ZÉRO RELIQUAT"
- Utiliser systématiquement `EnergyNetwork.Quantize()` pour toute transaction d'énergie afin de garantir des paquets propres et éviter le drift flottant.

## 4. VÉRIFICATION FINALE
- Avant de répondre à l'utilisateur : « Est-ce que j'ai mis à jour le TODO ? Est-ce que j'ai écrit dans le DEVELOPMENT_LOG ? Est-ce que le code compile théoriquement sans erreur ? »
